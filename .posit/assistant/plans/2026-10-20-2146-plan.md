## Step 1: create `helper_functions/params_read.R`

One function, no side effects at source time (only defines the function).

```r
#' Ingest R Markdown YAML params
#'
#' Returns the `params` list for the current notebook, whether it is being
#' knit or run chunk-by-chunk in an editor (e.g. Positron "Run Cell"), where
#' `rmarkdown::render()` never creates `params`.
#'
#' @details
#' * Knitting (`knitr.in.progress` is TRUE): returns the `params` that
#'   `rmarkdown::render()` already created. YAML is not re-read.
#' * Interactive: re-reads the notebook's own YAML front matter on every call,
#'   so edits to the YAML take effect without `rm(params)`.
#'   Values are the raw YAML values from `rmarkdown::yaml_front_matter()`;
#'   `!r` expressions and `label`/`input`/`value` specs are not evaluated.
#'
#' @param rmd_path Path to the .Rmd to read. Default `NULL` uses the file in
#'   the active editor tab via `rstudioapi::getSourceEditorContext()`; that is
#'   only correct while the notebook is the focused tab.
#' @param envir Environment searched for `params` when knitting.
#'   Default `parent.frame()`.
#'
#' @return Named list of params.
#' @examples
#' \dontrun{
#' source(here::here("helper_functions", "params_read.R"))
#' params <- params_ingest()
#' params <- params_ingest(rmd_path = "path/to/notebook.Rmd")
#' }
params_ingest <- function(rmd_path = NULL, envir = parent.frame()) {
  if (isTRUE(getOption("knitr.in.progress"))) {
    if (!exists("params", envir = envir)) stop("...")   # knitting but no params
    return(get("params", envir = envir))
  }
  if (is.null(rmd_path)) rmd_path <- tryCatch(<rstudioapi path>, error = NA)
  if (invalid path / not file.exists) stop("Can't locate this .Rmd ... re-run.")
  p <- rmarkdown::yaml_front_matter(rmd_path)$params
  if (is.null(p)) stop("No `params:` block found in <path>.")
  p
}
```

Notes:
- Same behaviour as the current block (error if the path can't be found; no
  hardcoded fallback), plus an explicit error when the YAML has no `params`.
- Roxygen2 is installed, but this is a plain script rather than a package, so
  the roxygen comments are documentation in place and are not rendered to Rd.

## Step 2: edit the 27 notebooks

Every notebook has a `step1_libs_data` chunk under a "Libraries ..." heading.
Target layout inside that chunk:

1. `library()` calls (and any `options()` that follow them), unchanged.
2. New lines:
   ```r
   source(here::here("helper_functions", "params_read.R"))
   params <- params_ingest()
   ```
3. Directory definitions (`base.dir <- params$base.dir`, ...), unchanged.

Per-group handling:

- **23 notebooks where the old block is already inside `step1_libs_data`**
  (tut2 x4, tut4 parts 2-3, tut5 x4, tut7 x3, tut7-2 x3, tut9 x3, tut10 x2,
  tut12 x2; they share one identical 20-line block): replace the block in
  place with the two lines above.
- **4 notebooks with a standalone chunk** (tut3 parts 1-3 `ingest_params_if_necessary`,
  tut4 part 1 `params_read`): delete that chunk, and its lead-in text
  ("Params ingest" / "### Params ingest"), and insert the two lines into
  `step1_libs_data` immediately before the first line that references `params`
  (after the `library()`/`options()` lines). In tut4 part 1, `step1_libs_data`
  is a separate chunk further down, after the Description section.
- Leave the 'tut3' `clean params` chunk (`rm(params)`) as is.

Edit mechanics: scripted replacement in R (match on exact lines, as done last
time), preserving EOF newline state per file. Not using regex across chunks.

## Risks and open points

- `here::here()` relies on the `.Rproj` at the repo root. If a notebook is ever
  copied out of the repo, the `source()` line will fail with `here`'s message.
- `here` is a new dependency for the notebooks. It is already in `renv.lock`, so
  no installation is needed.
- Behaviour is unchanged from the current block, including the limitation that
  interactive runs need the notebook to be the focused editor tab (or
  `rmd_path` passed explicitly).
